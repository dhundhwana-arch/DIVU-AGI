# DIVU AI — frontend

Next.js 15 (App Router) application: public website, installable workspace and download page.

```bash
npm install
npm run dev      # http://localhost:3000  (development)
npm run build && npx next start   # production — required for the installable PWA
```

`API_PROXY_TARGET` (default `http://127.0.0.1:8000`) is where `/api/*` requests are proxied. The
browser only ever calls relative URLs, so no CORS setup or hard-coded backend host is needed.

## Routes

| Route | Purpose |
|---|---|
| `/` | Marketing website (hero, live build strip, platform, roadmap, security, install) |
| `/app` | Workspace: platform status, sign in / register, injection screening — PWA `start_url` |
| `/download` | Install to home screen + download the application package |

## Layout

```
public/    manifest.webmanifest · sw.js · offline.html · icons/ · og-cover.png · downloads/
src/
├── app/         layout (PWA metadata) · page (website) · app/page (workspace) · download/page
├── components/  brand header/footer, system panel, auth panel, security panel, install button
└── lib/api.ts   typed API client: auth, refresh, error envelope, endpoints
tailwind.config.ts · postcss.config.js · next.config.ts (API proxy rewrites)
```

## Progressive web app

* Icons are generated by `python ../scripts/generate_icons.py` (or `make icons` from the repo root).
* The service worker is registered **only in production builds** (`ServiceWorkerRegistrar`), so
  `next dev` hot-reload is never served stale code.
* `/api/*` is network-only: authenticated and live data are never cached.
* The downloadable package is produced by `make package` → `public/downloads/divu-ai-app.zip`;
  the `/download` page detects whether it has been built and shows `make package` if not.
